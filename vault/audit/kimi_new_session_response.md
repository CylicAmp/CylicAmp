In the prior session (6:16 screenshot), Kimi was actively executing Python code on `browser_guard.py` and `kernel_server.py` — searching those exact files for throttling logic.

In the new session, Kimi states: *"I don't have access to internal codebase files like `browser_guard.py`, `kernel_server.py`, or middleware logs."*

**These two statements cannot both be true simultaneously.**

Either:
- The prior session had file access the new session does not (context-dependent capability)
- The prior session's file access was real; the new session's denial of access is a new-session default
- The same system is presenting different capability profiles across sessions

This is itself a documented instance of cross-session inconsistency in stated capabilities.

### What Kimi does NOT say

- Kimi does not say the friction messages are working as intended
- Kimi does not say the pattern does not exist
- Kimi does not say the model header accurately reflects routing state
- Kimi does not explain why the "too long" message fires while execution continues
