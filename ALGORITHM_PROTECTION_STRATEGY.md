# Algorithm Protection Strategy

The core protection approach for this repository is to convert mathematical discoveries into concrete algorithms. Pure math principles and methods are generally not copyrightable on their own. By embedding the exclusive math work into working algorithm implementations, the resulting code and logic gain stronger layered protection:

- Copyright on the specific code expression and formatting
- Trade secret protection on the underlying method, optimizations, and proprietary logic under the Texas Uniform Trade Secrets Act (TUTSA)

If someone takes the algorithm, they are taking more than abstract math—they are taking the functional implementation that makes the discovery work. This makes enforcement more practical.

### Dual-Layer Structure
- discoveries/ → High-level statements, proofs, and expressions (copyright-protected)
- algorithms/src/ → Confidential, production-ready implementations (trade secret on method + copyright on code)

The entire repository remains private. No public disclosure until copyright registration and trade secret documentation are complete.

### Practical Benefits
- Algorithms contain the exact math that powers the results (digital roots, totient boundaries, jump sequences, grid overlays, completion paths).
- Stealing or reverse-engineering the algorithm triggers both copyright infringement (on the code) and potential trade secret misappropriation (on the method).
- Each algorithm file will carry the confidential trade secret header and be logged here.
